## Read the bundled Next.js 16 docs before changing framework code

This project runs Next.js **16.4.6** (App Router, React 19). Its APIs and file conventions differ from most training data. `AGENTS.md` says the same; its text is regenerated by `next dev`, so do not remove it from a diff.

Read the relevant guide in `node_modules/next/dist/docs/` before writing framework code. Project-specific notes:

- `proxy.ts` at the repo root is the Next 16 replacement for `middleware.ts` — do not rename it to `middleware.ts`.
- `next.config.ts` sets `cacheComponents: true` and `partialPrefetching: true`. DB-backed routes intentionally opt out of instant navigation with `export const instant = false` and/or `await connection()`; keep that pattern for new uncached-data routes.
- `revalidateTag` uses the two-argument form, e.g. `revalidateTag("sanra-from-prices", { expire: 0 })`. The one-argument form is deprecated.
- Dynamic `params` and `searchParams` are Promises and must be awaited.

## System overview

A single Next.js app with three surfaces:

- **Public storefront** — `app/page.tsx`, `app/products`, `app/sets`, `app/b2b`, `app/track`, `app/contact`; public APIs under `app/api/*`.
- **Internal admin** — `app/admin/**` (dashboard, products, rates, options, sets, orders, leads, CAD, audit) and `/api/admin/*`.
- **Documents and messaging** — server-generated PDF quotes, set quotes, bulk quotes and warranty certificates (`lib/pdf/*`), plus WhatsApp deep links.

The catalog is factory-direct steel furniture (tables, chairs, stands, racks, SS units, chair & table sets). Public pages are server components that read Supabase directly; interactive configurators are client components that call pricing APIs.

## Data access and privacy model

This is the most important architectural invariant.

- All database reads/writes use `createServerClient()` / `supabaseServer` from `lib/supabase/server.ts`. That client uses `SUPABASE_SERVICE_ROLE_KEY`, imports `server-only`, and bypasses RLS. Public pages, admin pages, server actions and route handlers all use it, then pass only safe, presentation-ready props to `"use client"` components.
- The Supabase **anon** client (`@supabase/ssr`) is used only for auth/session handling in `proxy.ts` and `lib/admin/auth.ts`. It is not used for catalog data.
- RLS is enabled on every public-schema table. `supabase/migrations/014_privacy_lock.sql` removes public policies, then adds SELECT-only policies for safe catalog tables (`products`, `product_visual_variants`, `configurator_options`, `product_type_option_groups`, `product_option_availability`, `product_sets`, `product_set_items`). Private tables have no anon/authenticated policies.
- **Never expose** cost, weight, labor, overhead, margin, discount, supplier or internal-note data in public APIs, public HTML, client component props, or public PDFs. Selling prices only.
- Public pricing responses may contain only the `ConfigPriceOutput` shape: `unit_price`, `total_price`, `discount_pct`, `bumper_included`, `requires_quote`. Use `stripCostFragments` (`lib/sanitize.ts`) when surfacing DB labels publicly.
- The browser never computes prices. `TableConfigurator`, `TypeConfigurator` and `SetConfigurator` POST selections to `/api/price`, `/api/set-price`, `/api/whatsapp-link`, `/api/quote-pdf`, etc.

## Pricing architecture

- `lib/pricing/configPrice.ts` is the entry point for public pricing. It looks up the SKU's product type and dispatches: `TABLE` uses the formula in `lib/pricing/pricingCore.ts`; `CHAIR` / `STAND` / `RACK` / `SS_UNIT` use `lib/pricing/typePricing.ts`. Input validation lives in `lib/schemas.ts`.
- Admin-entered direct prices take priority over formulas: `product_pricing_rules.direct_price` (with `granite_top_price` / `wood_top_price`) is returned before any cost calculation.
- `lib/pricing/fromPrice.ts` computes catalog "from" prices and caches them with `unstable_cache` (300 s, tag `sanra-from-prices`). Admin product/rate actions must call `revalidateTag("sanra-from-prices", { expire: 0 })` together with the relevant `revalidatePath` calls.
- Sets/bundles: `lib/pricing/setPrice.ts` and `setSummary.ts` price `product_sets` / `product_set_items` using the same per-product engine, with adjustments in the private `set_pricing` table.
- Fallback data is intentional. `FALLBACK_OPTIONS`, `FALLBACK_GROUPS`, `FALLBACK_RULES`, fallback material rates/globals, `KNOWN_PRODUCTS` and fallback product lists keep the site usable when Supabase is unseeded or unreachable. Public pages swallow DB errors and fall back rather than crashing.
- **Product-type mismatch to know:** the public pricing engine only recognises `TABLE | CHAIR | STAND | RACK | SS_UNIT` (`lib/productTypeConfig.ts`, `lib/schemas.ts`). The admin `ProductForm` now offers only `CHAIR | TABLE | CHAIR_TABLE_SET`; unknown/other types fall back to `TABLE` on the public product page. `CHAIR_TABLE_SET` products render `TableConfigurator` and use table pricing. This is separate from the `product_sets` bundle feature under `/sets` — don't conflate the two.

## Admin and authentication

- `proxy.ts` gates `/admin/**` and `/api/admin/**`: Supabase Auth via the anon SSR client, exact match against `ADMIN_EMAIL`, and an 8-hour idle cookie. Page requests redirect to `/admin/login`; admin API requests get `401`.
- Every admin page and server action also calls `requireAdmin()` (`lib/admin/auth.ts`) server-side. The admin layout requires it too.
- Server actions live in each admin folder's `actions.ts`. Pattern: `"use server"` + `requireAdmin()` + zod validation + `createServerClient()` + `writeAudit()` (`lib/admin/audit.ts`) + `revalidatePath` / `revalidateTag`. Client forms use `useActionState` and render `AdminActionResult` errors via `AdminToast`.
- Admin routes are unlinked, `noindex`, and `Cache-Control: no-store`. Never add admin links, `ADMIN_EMAIL`, or costing fields to public pages.
- The admin login is rate-limited (5 attempts / 15 min) and fails closed. `/api/track` also fails closed; public price routes fail open. The shared limiter is `lib/rateLimit.ts`, backed by the private `rate_limits` table.

## Public request flows

- `app/products/[sku]/page.tsx` loads the product, `configurator_options`, `product_option_availability`, visual variants and the public pipe spec, then renders `ProductConfiguratorLoader`, which dynamically picks `TableConfigurator` (`product_type === "TABLE"`) or `TypeConfigurator` (other types). `/sets/[sku]` renders `SetConfigurator`.
- `app/products/page.tsx` does catalog filtering/sorting server-side from `searchParams`.
- Public API routes validate with zod, call `checkSharedRateLimit`, return `Cache-Control: no-store`, and use generic error messages. Current limits: price/set-price 30/min, quote PDFs 10/min, WhatsApp links 20/min; B2B lead/CAD forms use a honeypot plus 5/hour; bulk pricing 20/min.
- PDFs use `pdf-lib` with Noto fonts in `lib/fonts`. Those files must remain covered by `outputFileTracingIncludes` in `next.config.ts` for the deployed route bundles.
- Order tracking (`/track`, `/api/track`, `/api/warranty-pdf`) requires the tracking code **and** the last 4 phone digits, returns one identical generic failure message, hashes IPs, enforces per-IP and per-code lockouts, and serves private order photos through short-lived signed URLs. Order/lead data is private.

## Database and migrations

- `supabase/migrations/*.sql` is the source of truth. Run in filename order; there is no `011` migration. `supabase-schema.sql` is an older compiled snapshot and lags the migrations — do not treat it as current.
- Public catalog tables: `products`, `product_visual_variants`, `configurator_options`, `product_type_option_groups`, `product_option_availability`, `product_sets`, `product_set_items`.
- Private (service-role only): `product_pricing_rules`, `material_rates`, `option_pricing`, `pricing_globals`, `set_pricing`, `orders` and order tables, `tracking_attempts`, `leads`, `cad_files`, `admin_audit_log`, `rate_limits`.
- Storage buckets: public `product-images`; private `order-photos` and `cad-files`.
- Setup, environment variables and verification flows are documented in `SETUP.md`; deployment and operations in `docs/DEPLOY.md` and `docs/OPERATIONS.md`.

## Conventions

- `@/*` maps to the repository root (`tsconfig.json`, `vitest.config.ts`).
- Add `import "server-only"` to any module that reads secrets or uses the service-role client. Add `"use client"` only to interactive components.
- Validate all external input with zod at the boundary: `lib/schemas.ts`, `lib/admin/validation.ts`, or route-local schemas.
- Money is handled in integer rupees and displayed with `formatINR` from `lib/format.ts` (en-IN grouping). Canonical URLs live in `lib/site.ts`; env-driven company and WhatsApp values live in `lib/company.ts`.
- Tailwind v4 is CSS-first: `@import "tailwindcss"` in `app/globals.css`, no `tailwind.config` file, with the Turbopack loader configured in `next.config.ts`.
- Tests use Vitest in a Node environment (`tests/**/*.test.ts`). They cover pure functions, guards, pricing, PDFs and route-level behavior; there are no component/browser tests.
- Do not edit `.next/` or `.build-check/` (generated; `.build-check` is gitignored).
